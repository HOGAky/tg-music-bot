# Техническое задание: Деплой tg-music-bot на Yandex Cloud

## 📋 Обзор

**Цель:** Адаптировать Telegram-бот для музыки к деплою на Yandex Compute Cloud с использованием облачных сервисов (Container Registry, Object Storage) для улучшения масштабируемости и надёжности.

**Текущее состояние:**
- Бот работает в режиме polling
- Локальный кэш mp3 на диске
- SQLite база данных
- Docker + docker-compose настроены
- Web App на aiohttp без HTTPS

**Целевое состояние:**
- Бот работает в режиме webhook
- Кэш mp3 в Yandex Object Storage (S3-совместимый)
- nginx для HTTPS termination
- Подготовка к миграции на PostgreSQL
- Автоматический деплой через Yandex Container Registry

---

## 🎯 Критерии успеха

1. ✅ Бот успешно работает в webhook режиме
2. ✅ MP3 файлы кэшируются в Yandex Object Storage
3. ✅ Web App доступен по HTTPS
4. ✅ Docker-compose разворачивается на Yandex VM одной командой
5. ✅ Логи сохраняются в файлы (prepare для Cloud Logging)
6. ✅ Конфигурация через .env без hardcoded значений

---

## 📝 Требования к изменениям

### 1. Переход на Webhook (вместо Polling)

**Описание:** Заменить polling на webhook для Telegram Bot API. Это обеспечит мгновенное получение обновлений и снизит нагрузку.

**Задачи:**

#### 1.1. Изменить `bot.py`
- [ ] Добавить параметр конфигурации `WEBHOOK_ENABLED` (bool, default false)
- [ ] Добавить параметры `WEBHOOK_URL` (публичный HTTPS адрес бота)
- [ ] Добавить параметр `WEBHOOK_PATH` (путь для webhook, default `/webhook`)
- [ ] Реализовать условную логику:
  - Если `WEBHOOK_ENABLED=true` → использовать webhook
  - Если `WEBHOOK_ENABLED=false` → использовать polling (для dev)
- [ ] При webhook режиме:
  - Установить webhook через `bot.set_webhook()`
  - Запустить aiohttp сервер для обработки webhook запросов
  - Реализовать endpoint для webhook path
- [ ] При polling режиме → оставить текущую логику
- [ ] При остановке бота → удалять webhook (cleanup)

**Технические детали:**
- Webhook endpoint должен принимать POST запросы от Telegram
- Использовать `aiogram.webhook.aiohttp_server` или custom aiohttp handler
- Хранить webhook server runner для корректного shutdown

#### 1.2. Обновить `config.py`
- [ ] Добавить поля:
  ```python
  WEBHOOK_ENABLED: bool = False
  WEBHOOK_URL: str = ""  # e.g., https://bot.example.com
  WEBHOOK_PATH: str = "/webhook"
  WEBHOOK_SECRET: str = ""  # секрет для валидации webhook (опционально)
  ```

#### 1.3. Обновить `.env.example`
- [ ] Добавить новые переменные окружения с комментариями

### 2. Интеграция с Yandex Object Storage (S3)

**Описание:** Перенести локальный кэш mp3 файлов в Yandex Object Storage для персистентности и масштабируемости.

**Задачи:**

#### 2.1. Добавить S3 storage service
- [ ] Создать файл `services/storage.py`
- [ ] Реализовать класс `S3Storage` с методами:
  - `upload_file(file_path: str, key: str) -> str` - загрузка файла
  - `download_file(key: str, local_path: str) -> str` - скачивание файла
  - `file_exists(key: str) -> bool` - проверка существования
  - `delete_file(key: str) -> None` - удаление файла
  - `get_public_url(key: str, ttl: int = 3600) -> str` - получение публичной ссылки
- [ ] Использовать библиотеку `boto3` для работы с S3
- [ ] Поддерживать fallback на локальное хранилище (если S3 недоступен)

#### 2.2. Обновить `services/downloader.py`
- [ ] Добавить зависимость от `S3Storage`
- [ ] После скачивания файла → загружать в S3
- [ ] При повторном запросе → проверять S3 кэш перед скачиванием
- [ ] Очистка локального кэша после успешной загрузки в S3
- [ ] Сохранять S3 key в Track модели вместо локального пути

#### 2.3. Обновить `config.py`
- [ ] Добавить поля:
  ```python
  USE_S3_STORAGE: bool = False
  S3_ENDPOINT_URL: str = ""  # e.g., https://storage.yandexcloud.net
  S3_BUCKET_NAME: str = ""
  S3_ACCESS_KEY_ID: str = ""
  S3_SECRET_ACCESS_KEY: str = ""
  S3_REGION: str = "ru-central1"
  S3_CACHE_PREFIX: str = "musicbot/"
  ```

#### 2.4. Обновить `requirements.txt`
- [ ] Добавить `boto3>=1.34.0`

#### 2.5. Обновить `.env.example`
- [ ] Добавить S3 настройки с комментариями

#### 2.6. Обновить `database/models.py`
- [ ] В модели `Track` добавить поле `s3_key: str | None = None`
- [ ] Миграция: существующие записи с локальными путями (опционально)

### 3. Nginx для HTTPS Termination

**Описание:** Добавить nginx контейнер для обработки HTTPS запросов и проксирования на бот и Web App.

**Задачи:**

#### 3.1. Создать `nginx/nginx.conf`
- [ ] Настроить upstream для bot (webhook endpoint)
- [ ] Настроить upstream для webapp (Mini App)
- [ ] Настроить SSL termination (Lets Encrypt или собственный сертификат)
- [ ] Проксировать `/webhook` → bot:8080/webhook
- [ ] Проксировать `/app/*` → webapp:8080/app/*
- [ ] Проксировать `/api/*` → webapp:8080/api/*
- [ ] Проксировать `/healthz` → webapp:8080/healthz
- [ ] Добавить rate limiting (опционально)
- [ ] Добавить basic auth для админских endpoint (опционально)

#### 3.2. Создать `nginx/Dockerfile`
- [ ] Базовый образ: `nginx:alpine`
- [ ] Копировать nginx.conf
- [ ] Путь для SSL сертификатов: `/etc/nginx/ssl/`

#### 3.3. Обновить `docker-compose.yml`
- [ ] Добавить сервис `nginx`:
  ```yaml
  nginx:
    build: ./nginx
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/ssl:/etc/nginx/ssl
    depends_on:
      - musicbot
    restart: always
  ```
- [ ] Изменить порты musicbot: убрать публичные порты (только internal network)
- [ ] Добавить internal network для общения контейнеров

#### 3.4. Создать скрипт для SSL сертификатов
- [ ] Создать `scripts/setup-ssl.sh` для получения Lets Encrypt сертификата
- [ ] Или инструкции для использования собственных сертификатов

### 4. Обновление Docker-конфигурации

**Задачи:**

#### 4.1. Обновить `Dockerfile`
- [ ] Установить `boto3` (для S3)
- [ ] Добавить `.env` в `.dockerignore` (чтобы не коммитить секреты)
- [ ] Оптимизировать слои (cache pip install)
- [ ] Добавить healthcheck:
  ```dockerfile
  HEALTHCHECK --interval=30s --timeout=10s --start-period=5s --retries=3 \
    CMD python -c "import requests; requests.get('http://localhost:8080/healthz')"
  ```

#### 4.2. Обновить `docker-compose.yml`
- [ ] Добавить volume для персистентной базы данных (если останемся на SQLite)
- [ ] Добавить volume для логов (если нужно)
- [ ] Добавить environment variables для S3
- [ ] Настроить restart policy для всех сервисов
- [ ] Добавить logging driver (для Cloud Logging integration в будущем)

**Пример структуры:**
```yaml
services:
  musicbot:
    build: .
    container_name: musicbot
    restart: always
    env_file: .env
    volumes:
      - ./data:/app/data
      - ./logs:/app/logs
    networks:
      - internal
    healthcheck:
      test: ["CMD", "python", "-c", "import requests; requests.get('http://localhost:8080/healthz')"]
      interval: 30s
      timeout: 10s
      retries: 3

  nginx:
    build: ./nginx
    container_name: musicbot-nginx
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/ssl:/etc/nginx/ssl
    depends_on:
      - musicbot
    restart: always
    networks:
      - internal

networks:
  internal:
    driver: bridge
```

## 📌 Примечания

- Сохранять обратную совместимость с polling режимом (для локальной разработки)

- Healthcheck endpoint `/healthz` уже есть в webapp - использовать его
